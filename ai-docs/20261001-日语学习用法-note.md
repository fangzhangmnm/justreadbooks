## 2. 功能想法

**user 1001 表态**：「看来jrb加朗读功能不是bloatware，在学习语言的场景下面是神器。其实写作验证也有用」——朗读方向 user 认可；具体做法（下面第 1 条的形态、要不要高亮、默认开关）仍按 JRB 侧规矩报 user 批。其余各条仍是 Claude 提、待批。

1. **朗读（Web Speech API `speechSynthesis`，`lang=ja-JP`）**：零体积，用系统 TTS 声音；按段 / 按句读，当前句高亮（reading-while-listening：把字形挂到已有的听觉词库上）。这是 user 这次 telemetry 里最有用的那条信道。**第二个用途 = 写作验证**（user 原话「其实写作验证也有用」）：听自己写的稿子 / 听 AI 卡，耳朵能抓到眼睛滑过去的节奏问题、重复和拗口句；中文也要能读（`lang` 跟书走，不写死 ja-JP）。
2. **听 / 读两个测量模式**：同一章可以「只听不看」或「只看不听」各读一遍，user 自己记哪段卡住；两者之差 = 解码能力。只是阅读器侧的开关，不用存数据。
3. **分词显示开关**（可选）：装订时预分词，阅读器里切换「原文 / 词间加空格」。注意 validation 用原文测，空格只用于练习。
4. 查词见 W-191；validation 书默认不挂词典。
