# JRB 迁库：store 0.15.2 → 2.1.2、gallery 0.4.0 → 0.8.5、workbench-elements 0.1.0 → 0.1.2 —— 行为差异表 + 开关决定

> created 20261021 by Claude Fable 5.1 · as-of v0.2.18 / 2026-10-21 · 家族周账 `weekly/20261021-family-todo.md` F-56 的 JRB 那半（§6 分道 3）。
> 口径：按 user 10-18 的分法「一半机械、一半行为变更」——机械那半 = tsc 报的编译错误（§4）；行为那半 = 下面三张表逐版过，每一行写清 JRB 碰不碰、开不开、为什么。WeebPaint（分道 2）用同一张表对口径：§1 / §2 里标「**全家族**」的行两边应一致。
> 读者 app 的前提（判断全部基于它）：**JRB 永不改写既有书**（`file.save()` 只在 `src/books.ts` 的上传，lint 守着），所以库里「保存撞 412 → 冲突面」那条主路在 JRB 几乎不发生；书是用户的作品（一等），阅读位置 / 切章规则是游标（collection），语音包是三等资源（不走 store）。

## 0. 结论一句话

- **store 2.x 的新开关 JRB 一个都不开**：`streaming` 不传、`docKinds` 不带 `tier`（书 = 一等作品 = 0.18 行为）、`transport` / `pushRetry` 用默认（= 0.17.0）、`openLineageFromDurable` 默认开。和 WXHW v2.3.42 / MoonSinger 同口径。
- **三处行为跟着库换（都是 user 已拍板的家族决定，不是本次新造）**：① 冲突面主按钮改「云端覆盖本地」、措辞按 `cloudState` 分（user 10-16「一切对齐」「默认云端才是 authority」「冲突面文案用『云端覆盖本地 / 本地覆盖云端』」）；② 书架卡片的「推送到云端」退场，换成图库包的「处理…」→ `file.resolve()` 三选一（user 10-16「禁止越狱」；周账 §0-2 点名的就是这个按钮）；③ 醒来 / 回线 / 登录后 / 手动刷新那次追新 `trustHints:false`（库 0.18.1 发版说明写明的消费方义务）。
- **两件要 user 定的**（§5）：未登录时拖进来的书怎么上云；书架要不要露备份箱页签（本次照 WXHW 加上了，不要就撤）。

## 5. 要 user 定的（本次没替你定）

1. **未登录 / 离线时拖进来的书怎么上云。** 核了库源码（`create-store.ts save()`）：`tryPush:false` 的保存**直接返回、不进离线补推队列**——那条队列只收「推过但没落地」的。JRB 上传时 `tryPush = 已登录 ∧ 在线`，所以未登录拖进来的书是本机唯一副本，**回线不会被问、也不会自动推**（CLAUDE.md 原来写的「回线问一次再推」只对「推到一半断网」成立，这次改掉那句）。以前的出路 = 卡片「推送到云端」；现在 = 卡片「处理…」→ 面里选「本地覆盖云端」（`cloudState: never` = 第一次上传）。要不要在登录后多一步「有 N 本书只在本机，现在传上去吗？」（问一次 → `files.dirty.pushAll()`，撞名的留着不覆盖）——这是新行为，等你一句话。不加的话现状可用、只是要人手动处理每一本。
2. **书架的回收站栏现在是两页签（回收站 / 备份箱）+ 清空。** 备份箱 = 冲突面里选输的那份；读者 app 几乎不会产生，但产生了总得有地方看、有地方清（照 WXHW v2.1.23）。觉得多余就说，撤回只有外壳那几行。
3. （已按家族决定做，只报备）冲突面主按钮 = 云端覆盖本地；「推送到云端」退场。
